# AGENTS.md

MV3 browser extension: themes chatgpt.com (72 named themes from the 1.x popup, or custom: accent, bubble, bubble text, send button, send button text, page surface) with automatic WCAG contrast repair. One source, builds for Chromium + Firefox. Published on Chrome Web Store (id `eojjhpainjcepfniefegkdjjemhigmgh`); not on AMO.

## Layout
- `src/lib/` pure logic, unit tested: `color.js` (parse, OKLCH, WCAG, ensureContrast, HSV), `discover.js` (find tokens in CSS rules), `theme.js` (palette math, REFERENCE palette, `rolesFor`, `readable` safety net, surface spec/`tintNeutral`), `css.js` (build override stylesheet), `themes.js` (the 72 themes, original 1.x values), `settings.js` (v3 schema, 1.x and 2.0.0 migrations), `storage.js` (chrome.storage wrapper).
- `src/content/index.js` content script (document_start). `src/popup/` popup UI (`popup.js` DOM, `model.js` DOM-free logic, `fonts/` bundled DM Sans + OFL). `src/manifest.json` base manifest; `scripts/build.mjs` writes per-browser manifests into `dist/chrome`, `dist/firefox` (esbuild IIFE bundles, unminified for store review).
- `test/fixtures/chatgpt-*.json` captured chatgpt.com CSS rules (`:root` + theme-class rules with custom props).

## Commands (Node >= 22.12; `/opt/homebrew/bin/node` on Trevor's Mac, default shell node is 20)
- `npm run build | test | lint | zip` ; `npm run check` = all.
- Offline popup check (headless, real keyboard): `node scripts/e2e-popup.mjs`. Vitest drives popup.html in jsdom (`test/popup.test.js`).
- Live checks (headed browser, NOT CI; Cloudflare blocks headless): `node scripts/e2e-live.mjs`, `e2e-themes.mjs` (12 themes x light/dark, compares painted colours with the engine), `e2e-upgrade.mjs` (v1.1.0 -> current migration), `e2e-firefox.mjs` (needs `brew install geckodriver`, stock Firefox), `screenshots.mjs` (README images), `capture-fixture.mjs` (fresh CSS fixture). Headed Chromium + `--disable-blink-features=AutomationControlled` + no `--enable-automation` gets past Cloudflare on chatgpt.com.
- Chromium unpacked extension id = sha256(realpath) first 32 hex mapped 0-f -> a-p (used by scripts to open popup.html).
- Firefox WebDriver: open extension pages from chrome context (`--allow-system-access`), using the runtime WebExtensionPolicy hostname. Install the local ZIP by `path`; Selenium's Base64 install left Windows Firefox referring to a deleted addon-test XPI (active addon, but empty popup and no content script). `ACCENTS_TEST_PROFILE` reuses a persistent test profile.

## How theming works (ChatGPT as of 2026-11-10)
- ChatGPT uses StyleX: hashed var names (`--x1e4keym`), atomic classes. Built-in accent setting = theme class on `<html>` (blue `x13qp82k` default; ~10 variants) shaped `.X.X, .X.X:root { --a; --b; ... }`, defaults in `:root, .xsajpkq`.
- Light/dark: lightningcss polyfill `var(--lightningcss-light,A)var(--lightningcss-dark,B)`; ChatGPT's Appearance=Dark sets `color-scheme: dark` on html. We emit native `light-dark(A, B)`, which follows the same color-scheme (verified live).
- discover.js: cluster theme classes sharing var names; accent cluster = >=4 classes spanning >=4 hue buckets. Reference theme = has mode-invariant chromatic value (the fill), closest to hue 265. Fill = chromatic value equal in light and dark (text/tint are pairs). Neutrals = achromatic vars with light != dark in any `:root, .Y` group.
- Base class `.xsajpkq` is on `<body>` too and RESETS raw accent tokens to black/white there; themed colors reach the UI via `:root`-declared semantic aliases resolved at html. Some controls ("Log in" pill: bg=text-primary, fg=raw on-accent token) depend on that reset. So accent overrides go on `:root` + theme classes ONLY; neutral-tint overrides go on `:root` + base classes. Mixing these up = invisible button text (seen at 390px dark).
- css.js: selectors are repeated x5 (beats `.X.X:root` = 0,3,0). Per token (role recognised from ChatGPT's own blue palette in `REFERENCE`, so a repaint of it degrades to "derived from accent"): fill family (light or dark value == reference fill) -> `roles.submit` (the send-button colour); pure grey (C<0.008) -> `roles.onSubmit`; token == REFERENCE tint -> bubble bg; light == REFERENCE onTint and dark == REFERENCE dark onTint -> bubble text; other surfaces -> retint; foreground (links, accent text) -> retint of accent (or `roles.link`) + ensureContrast vs the page surface (and the derived bubble when the bubble is not user-picked). var()/color-mix exprs restated verbatim.
- Roles (settings.roles): bubbleBg/bubbleText/submitBg/submitText/link, each hex or null (null = derived from accent `settings.light`). `readable()` is the safety net: a passing pair is returned untouched; failing coloured text keeps hue and moves the shortest way; failing grey/white text flips to onColor(bg). Minimums: bubble text 4.5 (7 under prefers-contrast: more), send glyph 3 (4.5 under more; it is a graphic, WCAG 1.4.11). The 7 themes this touches are pinned in test/roles.test.js.
- DECISION: ChatGPT draws the accent circle (send button, and the logged-in voice button) with ONE token. It follows the theme's Submit colour; accent drives accent text/links. 1.x had accent = voice button, submit = send arrow. Not separable without DOM selectors; only logged-out UI was ever visible.
- Surfaces (settings.surface {kind default|dark|light|custom, color}): `surfaceSpec()` -> hue + strength (colour's chroma) applied to BOTH modes as a lightness-preserving tint; lightness reshaped only in the colour's own mode (dark colours: opaque dark greys remapped onto it, incl. logged-out dark page `#000`; near-white: slight brightening). Never forces a dark page in light mode (that made text unreadable in 1.x). Logged-out page bg tokens differ from logged-in (#000/#fcfcfc vs #212121/#fff).
- Legacy named tokens (`--theme-user-msg-bg` etc., pre-StyleX ChatGPT) only emitted if a page stylesheet still declares them.

## When ChatGPT changes (re-fix playbook)
1. `npm run build && node scripts/e2e-live.mjs`. First line prints discovery status (accentTokens/neutralTokens). Popup shows a warning when `local.status.ok` is false.
2. If discovery fails: `node scripts/capture-fixture.mjs test/fixtures/chatgpt-<date>.json`, point a test at it, adjust heuristics in `discover.js` (`THEME_SELECTOR`, `ROOT_SELECTOR`, `parseValue` for new light/dark syntax). Keep the old fixture's tests passing.
3. If discovery works but colors look wrong: check which token an element uses (elementFromPoint -> matched rule -> var chain) and the classification thresholds in `css.js recolorToken`. Update `REFERENCE` in theme.js if OpenAI repaints its blue palette.
4. Recapture README shots with `scripts/screenshots.mjs`.

## Hazards
- Only logged-out chatgpt.com has been verified (no account available). Logged-in UI may use extra groups.
- Content script must never throw into the page; everything is try/catch'd and degrades to no styling. Cached tokens are candidates only: validate current CSS before rendering; a null discovery must clear tokens, remove overrides and write failed status even with zero rules.
- No-flash: ChatGPT can paint (FCP ~140 ms on a fast reload) before the async extension-storage read + stylesheet `load` task finish (override lands ~160-300 ms), so a stock frame showed on fast loads. Fix: `render()` writes `{build, css}` to chatgpt.com `localStorage["chatgpt-accents-for-all:paint"]`; `start()` applies it synchronously when `<html data-build>` matches, before any site CSS. `rediscover()` treats "no themeable rules yet while readyState != complete" as inconclusive (keeps the paint, writes no status). Cache misses (first load after install, first load after a ChatGPT deploy, site data cleared) still go through validation and can flash once.
- storage.sync quotas: popup writes `local.live` per change (instant repaint) and debounces `sync.settings` (400 ms, flushed on pagehide). Content picks the newer by `updatedAt`.
- Native `<input type=color>` closes Firefox popups: the popup disables pointer on it there (`html[data-native-picker=off]`) and the hex field is the control. Chromium uses the native picker.
- Popup keeps the 1.x footprint (352px content + 14px padding = 380px). Cards are `role=radio` in a `radiogroup` (one tab stop, arrows move AND select, 2 columns); hidden tab panel is `inert`. DM Sans is bundled (latin subset, OFL in `src/popup/fonts/`); never load remote fonts.
- Storage: `sync.settings` v3 (`theme` id/"custom", `light` = accent, `dark`, `roles`, `surface`), `sync.saved` (max 24, worst case ~7 KB; must stay under the 8 KB sync item quota, tested). `migrate()` handles 1.x `themeVars`/`savedThemes` (preset matched by accent+bubble+submit+surface; fixtures copied from 1.1.0 in `test/fixtures/v1-presets.json`) and 2.0.0 settings (preset id -> same-named theme; custom keeps accent/dark/tint-as-surface). 2.0.0's separate dark accent has no popup UI any more (kept in schema; cleared on edit).
- `npm` 11 warns about blocked install scripts; esbuild still works through its optional platform package.
- Version lives in both `package.json` and `src/manifest.json`; build fails if they differ.
