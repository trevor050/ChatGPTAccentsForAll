# AGENTS.md

MV3 browser extension: themes chatgpt.com (72 named themes from the 1.x popup, or custom: accent, bubble, bubble text, send button, send button text, page surface) with automatic WCAG contrast repair. One source, builds for Chromium + Firefox. Published on Chrome Web Store (id `eojjhpainjcepfniefegkdjjemhigmgh`); not on AMO.

## Layout
- `src/lib/` pure logic, unit tested: `color.js` (parse, OKLCH, WCAG, ensureContrast, HSV), `appshell.js` (current ChatGPT shell: semantic vars by data-theme/preset scope), `effect.js` (effect check: probes + verdict), `discover.js` (old StyleX shell), `theme.js` (palette math, REFERENCE palette, `rolesFor`, `readable` safety net, surface spec/`tintNeutral`), `css.js` (`buildPlan` -> {css, expect}: stylesheet + intended colour per var), `themes.js` (the 72 themes, original 1.x values), `settings.js` (v3 schema, 1.x and 2.0.0 migrations), `storage.js` (chrome.storage wrapper).
- `src/content/index.js` content script (document_start). `src/popup/` popup UI (`popup.js` DOM, `model.js` DOM-free logic, `diagnostics.js` Copy-diagnostics text (allowlist), `fonts/` bundled DM Sans + OFL). `src/manifest.json` base manifest; `scripts/build.mjs` writes per-browser manifests into `dist/chrome`, `dist/firefox` (esbuild IIFE bundles, unminified for store review).
- Icon: source `assets/icon/icon.svg` (128 grid -> 48/64/96/128) plus hand-drawn `icon-32.svg`/`icon-16.svg` for the toolbar; `node scripts/icons.mjs` (Playwright Chromium) writes `src/icons/*.png`, which are committed. Swatch bubble, tail right, indigo ramp #a9aeff/#8288ff/#5f63e6; no rainbow, nothing resembling OpenAI marks.
- `test/fixtures/chatgpt-*.json` captured chatgpt.com CSS. `-2026-11-10` = old StyleX shell. `-signed-in-2026-11-11` (Arc, linear preset, dark) and `-logged-out-2026-11-11` (codex preset): theme-scope rules, component re-declarations, var() colour usages, aliases. Style data only; never put page text/ids in fixtures.

## Commands (Node >= 22.12; `/opt/homebrew/bin/node` on Trevor's Mac, default shell node is 20)
- `npm run build | test | lint | zip` ; `npm run check` = all.
- Offline popup check (headless, real keyboard): `node scripts/e2e-popup.mjs`. Vitest drives popup.html in jsdom (`test/popup.test.js`).
- Live checks (headed browser, NOT CI; Cloudflare blocks headless): `node scripts/e2e-live.mjs`, `e2e-themes.mjs` (12 themes x light/dark, compares painted colours with the engine), `e2e-upgrade.mjs` (v1.1.0 -> current migration), `e2e-firefox.mjs` (needs `brew install geckodriver`, stock Firefox), `screenshots.mjs` (README images), `capture-fixture.mjs` (fresh CSS fixture). Headed Chromium + `--disable-blink-features=AutomationControlled` + no `--enable-automation` gets past Cloudflare on chatgpt.com.
- Chromium unpacked extension id = sha256(realpath) first 32 hex mapped 0-f -> a-p (used by scripts to open popup.html).
- `scripts/launch.mjs` launches every Chromium script. `ACCENTS_BROWSER=<chrome.exe|msedge.exe>` uses an installed browser: branded Chrome >= 137 ignores `--load-extension`, so it loads via browser-level CDP `Extensions.loadUnpacked` (+ `--enable-unsafe-extension-debugging`, pipe) and uninstalls on close. `ACCENTS_TEST_PROFILE=<dir>` reuses one profile (on Trevor's PC, Chromium starting a brand-new profile from a non-interactive/SSH context logged a failed Windows sign-in; 10 in 10 min locks the account).
- Firefox WebDriver: open extension pages from chrome context (`--allow-system-access`), using the runtime WebExtensionPolicy hostname. Install the local ZIP by `path`; Selenium's Base64 install left Windows Firefox referring to a deleted addon-test XPI (active addon, but empty popup and no content script). `ACCENTS_TEST_PROFILE` reuses a persistent test profile.

## How theming works (ChatGPT as of 2026-11-11)
- BOTH logged-out and signed-in chatgpt.com now run one Tailwind-v4-style shell (build 54e1c8b5, verified 2026-11-11). Signed-in seen in Arc with real account; logged-out via fetched HTML+CSS (`class="chatgpt-theme"`, preset `codex`). The StyleX path (below) is kept but no longer matches either.
- `<html data-theme=light|dark>` set by an inline bootstrap from `data-appearance-mode` (light/dark/system), plus `data-appearance-preset` (~30 presets: linear, codex, dracula, ...), `data-codex-window-type`. Inline `<style data-codex-app-themes>` (rewritten by JS from localStorage `codex.browser.appThemes.v1` and on preset change, no load event -> MutationObserver on head) = `@layer theme { :root:not([data-theme]),[data-theme=""],[data-theme="light"]{...} [data-theme="dark"]{...} }`. Main sheet has `:where(:root[data-appearance-preset="X"]) :where([data-theme])` preset rules (lightningcss light/dark polyfill). Portals/code blocks carry nested `data-theme`.
- Roles: bubble `--color-background-user-message`/`--color-text-user-message` (utilities `.bg-user-message`, `.text-user-message`); send `--color-background-composer-primary`/`--color-text-composer-primary` (`.bg-composer-primary`); accent `--color-accent`, `--color-background-accent-solid(-hover/-active)`, `--color-text-accent`, `--color-text-on-accent`, `--codex-base-accent`, `--app-color-*-accent`. `appshell.js roleFromName` maps names; hue-near-preset-accent values are a fallback. Excluded: palette primitives (`-500`, `chat-accent-green`), `other-user-message` (others' messages).
- HAZARD (why 2.0.0 did nothing signed-in): components RE-DECLARE role vars in `@layer components` (`.composer-ebIxkP{--color-background-composer-primary:var(--messaging-send-background,var(--color-background-primary-solid))}`, compact/unpersonalized bubbles). Setting vars on :root is not enough. `discoverAppShell` returns `components`; css.js mirrors them (`:is(sel)`x5, light-dark()).
- css.js emits app overrides UNLAYERED (beats every `@layer theme/components` rule regardless of specificity) on the page's own mode selectors, boosted `:is(S)`x5, separate light and dark blocks (no reliance on color-scheme except components).
- Effect check (content): after paint, wait 0.7/2.5/7 s; collect colour decls that are exactly `var(--x)` (+ alias chains) for overridden vars, querySelectorAll those selectors, read computed colour WITH our sheet and with `sheet.disabled=true` (same task, never painted). Counts only colours our sheet changed; ours==theirs samples are ignored (white glyph coincidence made a broken build look healthy once). No change anywhere after the last try -> remove overrides, clear paint cache, status `{ok:false, reason:"no-effect"}`; retried on settings change, tab shown, SPA URL change. Bubble/send failing while others pass = `partial`.
- Popup asks the ACTIVE tab (`tabs.sendMessage` "chatgpt-accents:status"; no tabs permission needed) and only warns about that tab; storage `local.status` is last-writer-wins across tabs, used only for diagnostics.
- Old StyleX shell (logged-out until ~2026-11-10): hashed vars, theme classes `.X.X, .X.X:root`; discover.js clusters accent classes; overrides on `:root` + theme classes only (base class on body resets raw tokens); `REFERENCE` in theme.js = its blue palette, still the template for derived roles.
- Roles (settings.roles): bubbleBg/bubbleText/submitBg/submitText/link, each hex or null (null = derived from accent). `readable()` safety net: bubble text 4.5 (7 prefers-contrast:more), send glyph 3 (4.5). Accent text is checked against the shell's real page surface (`--app-color-background-surface`).
- Surfaces: `surfaceSpec()` tint applied to neutral vars (StyleX neutrals; app-shell achromatic background/surface/text/border vars of the active scopes).
- Legacy names (`--theme-user-msg-bg`, ...) emitted only if a sheet declares them; signed-in conversation pages still ship them but nothing visible uses them (the owner's 2.0.0 report: popup healthy, page unchanged).

## When ChatGPT changes (re-fix playbook)
1. Popup Advanced -> Copy diagnostics (shell, preset/mode attrs, overridden vars, effect verdict with selector/actual/wanted). Or `npm run build && node scripts/e2e-live.mjs` (headed; checks computed send-button colour + effect state).
2. If discovery fails: `node scripts/capture-fixture.mjs test/fixtures/chatgpt-<date>.json`, point a test at it, adjust heuristics in `discover.js` (`THEME_SELECTOR`, `ROOT_SELECTOR`, `parseValue` for new light/dark syntax). Keep the old fixture's tests passing.
3. If discovery works but colors look wrong: check which token an element uses (elementFromPoint -> matched rule -> var chain) and the classification thresholds in `css.js recolorToken`. Update `REFERENCE` in theme.js if OpenAI repaints its blue palette.
4. Recapture README shots with `scripts/screenshots.mjs`.

## Hazards
- Signed-in testing: owner's own Arc session only, via AppleScript `execute javascript` on a tab you opened (style data only, never innerText/ids), `arc://extensions` reload via shadow-DOM `#dev-reload-button` click. Never sign in, never change ChatGPT settings, close your tab after. Arc on another Space = hidden tab: timers throttled, no rAF, screenshots stale.
- Content script must never throw into the page; everything is try/catch'd and degrades to no styling. Cached tokens are candidates only: validate current CSS before rendering; a null discovery must clear tokens, remove overrides and write failed status even with zero rules.
- No-flash: ChatGPT can paint (FCP ~140 ms on a fast reload) before the async extension-storage read + stylesheet `load` task finish (override lands ~160-300 ms), so a stock frame showed on fast loads. Fix: `render()` writes `{build, css}` to chatgpt.com `localStorage["chatgpt-accents-for-all:paint"]`; `start()` applies it synchronously when `<html data-build>` matches, before any site CSS. `rediscover()` treats "no themeable rules yet while readyState != complete" as inconclusive (keeps the paint, writes no status). Cache misses (first load after install, first load after a ChatGPT deploy, site data cleared) still go through validation and can flash once.
- Live scripts in a reused profile: ChatGPT restores the unsent composer draft, and also renders a hidden mobile `<textarea>`. Type only into the visible composer (`:visible`) after clearing it, or old text leaks into prompts/screenshots.
- storage.sync quotas: popup writes `local.live` per change (instant repaint) and debounces `sync.settings` (400 ms, flushed on pagehide). Content picks the newer by `updatedAt`.
- Native `<input type=color>` closes Firefox popups: the popup disables pointer on it there (`html[data-native-picker=off]`) and the hex field is the control. Chromium uses the native picker.
- Popup keeps the 1.x footprint (352px content + 14px padding = 380px). Cards are `role=radio` in a `radiogroup` (one tab stop, arrows move AND select, 2 columns); hidden tab panel is `inert`. DM Sans is bundled (latin subset, OFL in `src/popup/fonts/`); never load remote fonts.
- Storage: `sync.settings` v3 (`theme` id/"custom", `light` = accent, `dark`, `roles`, `surface`), `sync.saved` (max 24, worst case ~7 KB; must stay under the 8 KB sync item quota, tested). `migrate()` handles 1.x `themeVars`/`savedThemes` (preset matched by accent+bubble+submit+surface; fixtures copied from 1.1.0 in `test/fixtures/v1-presets.json`) and 2.0.0 settings (preset id -> same-named theme; custom keeps accent/dark/tint-as-surface). 2.0.0's separate dark accent has no popup UI any more (kept in schema; cleared on edit).
- `npm` 11 warns about blocked install scripts; esbuild still works through its optional platform package.
- Version lives in both `package.json` and `src/manifest.json`; build fails if they differ.
